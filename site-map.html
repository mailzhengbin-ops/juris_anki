1全局架构：一次请求的生命周期

这是 Inertia 单页应用：前端不自己调 API，而是用 JavaScript 发 Inertia 请求，后端渲染页面时把数据以 props 一起返回，React 组件直接消费。全站唯一例外是 markdown 导入（POST multipart 文件上传）。

层干什么位置
路由URL 映射到控制器。核心学习流在 web.php，管理端在 admin.php（套 EnsureAdmin 中间件），设置与认证在 settings.phproutes/*.php
控制器薄层：校验输入、调用服务、返回 Inertia 页面或重定向app/Http/Controllers/
服务层真正的业务逻辑：背诵、范围、统计、导入、错题本各一个深模块app/Services/
模型 / 表7 张表承载全部数据（§5），范围勾选与背诵进度各有巧思app/Models/
前端页面Inertia 渲染到 resources/js/pages/，消费 props，经 Wayfinder 类型化函数提交resources/js/pages/
浏览器 URL → Inertia 请求 → routes/*.php → Controller → Service → Model / DB → props JSON → pages/*.tsx
改功能时的第一问永远是：这个动作写不写库？ 只读展示 → 找 Controller 的 show/index 方法；写库 → 找 POST 路由和背后的 Service。

2核心学习流（每天用的三页）

产品循环：选卡（定范围）→ 背诵（翻卡打分）→ 统计（看结果）。三页共用一套概念：来源（SourceType：自选卡/错题本）、范围（Scope）、评价（Rating：认识/模糊/忘记）。

7三大核心设计决策（改代码前必读）

① 背诵进度 = 实时推导，无冗余存储

进度不存"背到第几张"。每次 GET /recite，RecitationService::state() 用"当前范围卡片 − 已评价卡片"实时算出下一张。中途改范围、撤销、再背一轮都天然正确。阶段判定（empty/fresh/active/completed）也在这里推导，前端只消费 phase 字段。

② 范围勾选反向存储（排除集）

默认全选 = 数据库零行。勾上卡片 = 删掉它的排除记录，取消 = 插入一条。范围 = 源内全部卡片（卡组树顺序）− 排除集。写库唯一入口是 ScopeService::toggle() / apply()。

③ 错题本在册 = 单一规则

由唯一规则决定：最新一次评价是模糊/忘记 = 在册，认识 = 出册（Rating::enrollsInMistakeBook()）。规则集中在 MistakeBookService.php，被范围服务和背诵服务共用。

9一次完整的旅程：用户按了「认识」

打分不经过页面跳转，数据随响应直接回到同一个页面——这是 Inertia 应用和传统网站最不一样的地方。

① 用户按 1（认识） → ② useAction 提交 POST /recite/rate → ③ 路由匹配 → ReciteController@rate → ④ 校验 rating → ⑤ RecitationService::rate() 写库 → ⑥ 重新算出 state() → ⑦ 新 state 随响应返回 → 页面直接更新
步骤发生什么在哪看代码
① 用户按 1RatingBar 捕获快捷键/点击，调 rate actionresources/js/pages/recite/index.tsx
② 提交useAction 统一包装：请求、loading、错误 toastresources/js/hooks/use-action.ts
③ 路由POST /recite/rate 匹配到控制器routes/web.php → ReciteController@rate
④ 校验card_id 必须存在，rating ∈ {known, fuzzy, forgotten}app/Enums/Rating.php
⑤ 写库范围校验 → 无开放任务则建 Task → 追加一条 Evaluationapp/Services/RecitationService.php
⑥ 重新推导用"范围 − 已评价"算出下一张卡和新进度RecitationService::state()（纯投影，不写库）
⑦ 页面更新新 state 直接渲染：进度条前进、换下一张卡recite/index.tsx（React 收到新 props）
注意 ⑤ 和 ⑥ 的区别：rate() 写库，state() 只读。这也是"撤销"实现简单的原因——删掉最后一条 Evaluation 再重新推导一遍即可。

10动手练习：三个定位题

先自己想答案，再点开核对。

练习 1 · 找文件（简单）

背诵页有个"再背一轮"按钮。它在前端哪个文件、走后端哪个控制器方法？

查看答案
前端 pages/recite/index.tsx（router.get(recite?start=1)）；后端 ReciteController@show 收到 start=1 时强制回 fresh。

练习 2 · 找服务（中等）

"卡片最新评价是模糊/忘记 = 进错题本"这条规则在哪个文件？它被谁共用？

查看答案
app/Services/MistakeBookService.php（规则单点：Rating::enrollsInMistakeBook()），被 ScopeService（错题本源）和 RecitationService（卡片在册标记）共用。见 §7 决策 ③。

练习 3 · 读链路（挑战）

用户在选卡页"调整范围"对话框里取消勾选了一张卡并点确认。写下从点击到数据落库的完整路径（提示：4 步，涉及 2 个文件、1 个服务、1 张表）。

查看答案
① select/index.tsx 本地草稿移除该卡 id → 确认时组装 card_ids[]；② POST /scope/apply → ScopeController@apply；③ ScopeService::apply() 整组替换排除集；④ 该卡（及所有未勾选卡）插入 scope_exclusions 表 —— 注意是反向存储：落库的是"不背的卡"。
